# Aisha · GTM Engineer

I'm a GTM Engineer, I help B2B companies set up outbound campaign systems to get them to book meetings/demos.

I work across three layers of go-to-market:

1. **GTM systems:** AI agents and workflows that power the sales, marketing and customer support teams.
2. **Outbound systems:** finding the right customers and reaching out to them.
3. **RevOps:** the CRM that keeps it all organised.

I take the manual work a revenue team does every day and turn it into systems that run on their own.

## 1. GTM systems: AI agents and workflows

Systems that take repeatable manual work off the GTM team, built with Claude, Clay and Python.

- **For sales.** Research agents that turn a LinkedIn URL into a full prospect profile, verified email and a suggested outreach angle, before every call or email.
- **For marketing.** Workflows that automate the repeatable parts of campaigns, research and content.
- **For customer support.** Systems that give the support team the right context and take routine work off their plate.

## 2. Outbound systems: finding and reaching customers

- **Signals.** Track news like funding, hiring and expansion to find accounts that are ready to buy.
- **Enrichment and list building.** Build target accounts, decision makers and verified emails in Clay.
- **Segmenting.** Group accounts by ICP, industry and look-alikes of a company's best case studies.
- **Messaging and copywriting.** Short, plain emails written for each segment, with one clear ask.
- **Sending.** Run the campaigns across email and LinkedIn with SmartReach and HeyReach.

## 3. RevOps: CRM

- **Salesforce and HubSpot.** Set up and run the CRM so the data stays clean and reps trust it.
- **Connected systems.** Push enrichment, research and outbound activity into the CRM automatically, with no copy and paste.

## How I work

1. **Map the process.** Find the manual steps and where the team loses time.
2. **Build the system.** Connect the tools, data and AI agents end to end.
3. **Ship it live.** Deploy it so the team uses it, then measure meetings booked and pipeline.
4. **Plan for what breaks.** Check limits, costs and failure points up front, so the system holds up on the hard days.

## Tools I use

Clay · Claude Code · Claude API · HubSpot · Salesforce · Python · Supabase · SmartReach · HeyReach · Vercel · GitHub
